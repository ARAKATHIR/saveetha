2 What is a Pointer? 📍

Every variable lives somewhere in the computer's memory. That place has an address. A pointer is a variable that stores an address of another variable.

🌍 Real-life analogy

A house 🏠 has things inside. A small paper with the house address 📝 is not the house. But with that paper you can go to the house and use what is inside. The paper is the pointer.

Two new symbols
  • &x means "the address of x".
  • int* p means "p is a pointer to an int". It can store the address of an int.
  • *p means "the value at the address stored in p".
int x = 10; int* p = &x; // p stores the address of x cout << *p; // goes to that address: prints 10

A pointer can be changed later to point to a different variable. If you print p itself, you see an address like 0x7ffe.... We will not print addresses here.

3 Pointer to an Object & the Arrow -> 🏹

A pointer can also store the address of an object. A pointer to a Student is written Student* p.

🌍 Real-life analogy

A remote control 📺 is not the TV, but it works the TV. A pointer works the object it points to. With an object we use the dot . With a pointer we use the arrow ->

✅ Dot or arrow?
Student s; // object ➜ use dot s.show(); Student* p = &s; // pointer ➜ use arrow p->show();

p->show() means the same as (*p).show(): "go to the object and call show()". The arrow is just shorter.

🎮 Dot or arrow? Tap your answer

Student s; is an object. Student* p = &s; is a pointer.

✅ Look carefully

p->marks = 95; changed the object s itself, because p points to s. So s.show() printed 95.

4 Making Objects with new & delete 🏨

We can create an object on demand using new. It gives us the address of the new object, so we keep it in a pointer. When we are done, we must remove it with delete.

🌍 Real-life analogy

You book a function hall 🏨 when you need it (new). You get a booking slip (the address). After the function you must return the hall (delete). If you forget, the hall stays booked for nobody!

  • Student* p = new Student("Asha"); makes the object and stores its address in p.
  • If the constructor needs no values, just write new Book.
  • Use it with the arrow: p->name
  • delete p; removes the object. Its destructor runs right then.
  • Objects made with new are not removed by themselves. If you forget delete, the destructor never runs. This mistake is called a memory leak.

5 The this Pointer: "Who is calling me?" 🙋

Many objects of one class share the same functions. So how does a function know which object called it? C++ secretly gives every member function a hidden pointer named this. It points to the object that called the function.

🌍 Real-life analogy

Many people use the same office phone ☎️. When someone says "I" or "me", it means whoever is speaking right now. this is the object's way of saying "me".

  • this is a pointer, so we use the arrow: this->name.
  • It exists only inside member functions.
  • We never create it. C++ gives it to us.

7 Using this When Names Clash ⚔️

The most common use of this: a constructor's parameter has the same name as a data member. Then name = name; is confusing. Plain name means the parameter. We write this->name for the member of the object.

🌍 Real-life analogy

Two people in a room are both called Ravi. To talk about yourself you say "my name" (this->name). To talk about the visitor you say "the visitor's name" (name, the parameter).

8 Pointer to a Derived Class: Base Pointer 🦴

A base class pointer can hold the address of a derived class object. This is allowed because a Dog is an Animal. But the pointer only knows about Animal, so through it we can use only the base class members.

🌍 Real-life analogy

A general remote 📺 labelled "Animal" has only the common buttons: eat, sleep. Even if the thing in front is a Dog, the remote has no bark button. A special Dog remote would have it.

✅ Rules
  • Animal* p = &d; ✅ base pointer ➜ derived object (allowed).
  • p->eat() ✅ eat() is in Animal.
  • p->bark() ❌ bark() is only in Dog. The pointer cannot see it.
  • Dog* q = &a; ❌ derived pointer ➜ base object (not allowed). Not every Animal is a Dog!

9 The Surprise: Same Function Name 😲

A derived class may write a function with the same name as one in the base class. A Dog object then uses its own version. But through a base pointer, C++ looks only at the pointer's type, so it calls the base version!

🌍 Real-life analogy

A box 📦 has a label "Animal" but a Dog is inside. If C++ only trusts the label, it treats the Dog like a general animal. The pointer's type is the label.

10 virtual: Look at the Real Object ✅

We can fix the surprise. Write the word virtual before the function in the base class. Now, through a base pointer, C++ looks at the real object and calls its own version.

🌍 Real-life analogy

This time C++ opens the box 📦 and looks at what is really inside. A Dog says Woof 🐶 and a Cat says Meow 🐱, even though both boxes are labelled "Animal".

✅ Remember
  • virtual void sound() is written in the base class.
  • Not virtual ➜ the pointer's type decides.
  • Virtual ➜ the real object's type decides.
  • A pointer can be changed to point to another object: p = &c;. One pointer, many forms!
