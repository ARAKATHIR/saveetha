2 What is a Constructor? 🔧

A constructor is a special function inside a class. It runs by itself at the moment an object is created. We never call it ourselves.

🌍 Real-life analogy

When you switch on a new phone 📱 for the first time, a welcome setup runs automatically. You did not press any "setup" button. A constructor is that automatic setup for an object.

✅ Three rules
  • The name is the same as the class name.
  • It has no return type, not even void.
  • It runs automatically when the object is created.

A constructor with no values in the brackets is called a default constructor.

3 Constructor with Values 🍕

A constructor can receive values. It is then called a parameterized constructor. The values go inside the brackets when we create the object.

🌍 Real-life analogy

When you order a pizza 🍕 you say the size and topping while ordering. The kitchen then makes exactly that pizza. The values you give while creating an object are used to set it up.

New word: parameter

A parameter is a small box in the brackets that receives a value. In Animal(string n), the box n receives the name. We then copy it: name = n;

Animal a("Tommy"); ↑ ↑ object value sent to the constructor
⚠️ Be careful

If a class has only a constructor that needs a value, you must give the value when you create the object. Animal a; would then be an error.

4 Constructors in Derived Classes 🏗️

When we create an object of a derived class, two constructors run: first the base class constructor, then the derived class constructor.

🌍 Real-life analogy

To build a house 🏠 you must first build the foundation (base). Only then can you build the walls (derived). The base is always ready before the child.

✅ Rule

Base first ➜ Derived next. This happens automatically. We do not write anything extra for it.

5 Sending Values to the Base Constructor 📨

What if the base constructor needs a value? The derived constructor must pass it on. We write a colon : after the brackets, then the base class name with the value. This is called an initializer list.

Dog(string n, int a) : Animal(n) { // Dog's own work }
  • Dog(string n, int a) receives two values.
  • : Animal(n) says "call Animal's constructor and give it n".
  • You can pass any value, such as n or even y + 1.
  • If the base class needs a value, the derived class must pass it.
🌍 Real-life analogy

A birth certificate 📜 needs the baby's name. The parents (derived constructor) take the name they received and hand it over to the office (base constructor).

6 Destructors & the Order of Calls 🔄

A destructor is the opposite of a constructor. It runs automatically when an object is removed. For our programs, that happens when main() ends.

✅ Rules for a destructor
  • Name = tilde ~ + class name, like ~Animal().
  • No return type and no values in the brackets.
  • Runs by itself when the object ends.
🌍 Real-life analogy

You put on socks first, then shoes 👟. To undress, you take off the shoes first, then the socks. Removing happens in the reverse order.

✅ Order

Constructors: Base ➜ Derived.
Destructors: Derived ➜ Base (reverse).

This program uses a chain: SportsCar inherits from Car, and Car inherits from Vehicle. Each class inherits from the one above it.

Good to know

If a class has two parents, like class C : public A, public B, the constructors run in the order the parents are written: A first, then B.

7 Abstract Classes 🎭

An abstract class is an incomplete class. It is made only to be a base for other classes. You cannot create an object from it.

🌍 Real-life analogy

Nobody can draw "a shape" ✏️. You can only draw a circle or a square. "Shape" is just an idea. It says: "every shape must be able to tell its area", but it does not say how. Each real shape decides for itself.

New idea: pure virtual function
virtual void area() = 0;
  • It has no body. It is only a promise: "my children will write this."
  • We write virtual at the start and = 0 at the end.
  • A class with at least one pure virtual function is an abstract class.
  • A child class must write the function (with a body). Then the child is a normal class and objects can be created.
  • If the child forgets, the child is also abstract.

8 Abstract Classes with Data & Constructors 🧰

An abstract class is still a class. It can have data members, a constructor and normal functions. Its children send values to it with the initializer list, just like in Section 5.

🌍 Real-life analogy

Every employee in a company has a name and joins in the same way. But what each one works on is different: a teacher teaches 📚, a driver drives 🚌. "Employee" is the abstract idea. Teacher and Driver are real jobs.

Teacher writes its own work(): it prints "<name> teaches students". It also passes the name up with : Employee(n).

Driver writes its own work(): it prints "<name> drives the bus". It also passes the name up with : Employee(n).

9 Member Classes: Objects Inside a Class 🚗

A class can keep an object of another class as one of its members. This is called a member object (also called containership). It shows a has-a relationship.

🌍 Real-life analogy

A car 🚗 has an engine ⚙️. The car is not a kind of engine. So the Engine is a part inside the Car. Inheritance says "is a". Member objects say "has a".

InheritanceMember object
Relationshipis-ahas-a
ExampleDog is an AnimalCar has an Engine
How we write itclass Dog : public AnimalEngine engine; inside Car
⚠️ Order of writing

The Engine class must be written before the Car class. Car can only use something that is already known.

10 Constructors with Member Objects 🔩

When we create a Car, its Engine member must be built too. The rules:

  • Member objects are built first, then the body of the Car's constructor runs.
  • To give the Engine a value, use the initializer list with the member's name: Car(int h) : engine(h)
  • Remember: for a base class we write the class name. For a member object we write the object name.
  • Removing is in reverse: Car's destructor first, then Engine's.
🌍 Real-life analogy

A factory fits the engine into a car body before the car is finished and handed over. When the car is scrapped, the car is taken apart first and then the engine is removed.

11 Nested Classes: A Class Inside a Class 🪆

A nested class is a class written inside another class. It belongs to the outer class.

🌍 Real-life analogy

Think of Russian nesting dolls 🪆. A smaller doll lives inside the bigger doll. A Keyboard class written inside a Computer class is like that.

New symbol: ::

The scope resolution operator :: means "that lives inside". Computer::Keyboard means "the Keyboard that lives inside Computer". We use it to create an object of a nested class.

✅ Do not mix up

Member object = an object kept inside a class (Section 9).
Nested class = a whole class (blueprint) written inside a class.

✅ Five golden rules
  • Constructor: same name as the class and no return type.
  • Constructors run Base ➜ Derived. Destructors run in reverse.
  • Pass values to the base with : Base(value).
  • A class with a pure virtual function is abstract. You cannot make an object of it.
  • Member objects are built before the body of the container's constructor.
