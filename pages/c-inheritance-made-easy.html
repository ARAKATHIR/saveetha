2 What is Inheritance? 🧬

Inheritance means one class gets (inherits) the things of another class. We do not need to write the same code again.

🌍 Real-life analogy

You get your eye colour and height from your parents 👨‍👩‍👧. Nobody teaches your eyes to be brown. You inherit them! You also have your own talents, like playing guitar 🎸.

Two names to remember

ClassOther namesJob
Base class 👨‍👩‍👧Parent class, Super classGives its members
Derived class 👶Child class, Sub classReceives the members and adds its own
✅ The "is-a" test

Use inheritance only when you can say "is a": A Dog is an Animal ✔️. A Car is a Vehicle ✔️. A Dog is a Car? ❌ No!

Why use it? 1) Write code once, use many times. 2) Saves time. 3) Fewer mistakes. 4) Easy to change.

3 How to write it: Syntax ✍️

To inherit, we write a colon : after the new class name. Then we write public and the base class name.

class Child : public Parent { // Child's own members };
  • : means "inherits from".
  • For now, always write public after the colon. Keep every member public too.
  • After this, a Child object can use the public members of Parent with the dot: c.eat()

4 Types of Inheritance at a glance 🗂️

There are 5 types. Tap each card to open it.

✅ Easy memory trick

Single, Multilevel, Hierarchical, Multiple, Hybrid → S M H M H. Next we study them one by one.

5 Single Inheritance 🧍➜🧍

One base class and one derived class.

🌍 Real-life analogy

A son gets his one father's surname and cricket skill 🏏. One father → one child class.

Animal ↓ Dog
✅ Look carefully

Dog never wrote name or eat(). It got them from Animal. That is inheritance!

6 Multilevel Inheritance 🔗

A chain: A → B → C. The last class gets things from all the classes above it.

🌍 Real-life analogy

Grandfather's house 🏠 goes to the father, and then to the son. Grandfather → Father → Son.

Vehicle ↓ Car ↓ SportsCar
✅ Remember

SportsCar inherits from Car, and Car inherits from Vehicle. So SportsCar can use start() from Vehicle too.

7 Hierarchical Inheritance 🌳

One base class and many derived classes.

🌍 Real-life analogy

One mother 👩 has many children. All children get her family name. Each child also has a different talent 🎨🎤.

Person ↙ ↘ Student Employee
✅ Remember

Each object has its own copy of name. Changing s.name does not change e.name.

8 Multiple Inheritance 👨‍👩‍👧

Two or more base classes and one derived class. We separate base classes with a comma.

🌍 Real-life analogy

A child gets driving skill from the father 🚗 and cooking skill from the mother 🍳. Two parents → one child.

Father Mother ↘ ↙ Child
✅ Remember

Syntax: class Child : public Father, public Mother. Write public before each parent.

9 Hybrid Inheritance 🧩

Hybrid means a mix of two or more types in one program.

🌍 Real-life analogy

A big family tree 🌳 is not just one pattern. Some people have one parent line, some get things from two sides. A family tree mixes everything!

Person ↓ Student Sports ↘ ↙ Player
✅ Remember

Here Person → Student is single. Student and Sports → Player is multiple. Mix of both = hybrid.

10 The Diamond Problem 💎⚠️

Look at this shape. A class gets from two parents, and both parents got from the same grandparent. The shape looks like a diamond 💎.

Person ↙ ↘ Student Employee ↘ ↙ TeachingAssistant
🌍 Real-life analogy

Ravi studies in a college and also works there as a Teaching Assistant. The college keeps a student file and an employee file. Both files contain his name. If someone asks, "What is Ravi's name?", which file will you open? 😵 Confusing!

New symbol: ::

The scope resolution operator :: means "from this class". ta.Student::name means "the name that came through Student".

11 Virtual Base Class ✅💎

A virtual base class fixes the diamond problem. The word virtual tells C++: "Keep only one copy of this base class and share it."

🌍 Real-life analogy

Now the college keeps one common file 📁 for Ravi's name. The student office and the employee office both look at the same file. One file, no confusion.

class Student : virtual public Person class Employee : virtual public Person class TeachingAssistant : public Student, public Employee
✅ Rule

Write virtual in the middle classes (Student and Employee), the ones that directly inherit from the top class. Do not write it in Person or in TeachingAssistant.

✅ Five golden rules
  • Inheritance = a child class gets the members of a parent class.
  • Syntax: class Child : public Parent
  • Use it only when "Child is a Parent".
  • Diamond problem = two copies of the top class → confusion (ambiguity).
  • Solution = virtual base class → only one shared copy.
